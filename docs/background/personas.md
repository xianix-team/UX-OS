# UX Designer OS — Initial Personas

These personas are intentionally focused on meaningful behavioural segments rather than fictional demographic detail.

They are working personas for product definition and should be validated later.

---

# Persona 1 — The Embedded Senior Product Designer

## Profile

**Role:** Senior Product Designer  
**Experience:** 8–15 years  
**Environment:** Established SaaS or enterprise product team  
**Project type:** Primarily brownfield

## Characteristics

- knows UX methodology well
- works on a mature product with years of accumulated complexity
- receives frequent feature and improvement requests
- collaborates closely with PMs, developers, and other designers
- works within an existing design system
- often has incomplete documentation
- increasingly uses AI to accelerate analysis, ideation, and documentation
- does not want a tool that forces a textbook UX process

## Pain Points

- important product knowledge exists across many tools and people's memories
- repeatedly explains the same product context to AI tools
- difficult to understand why some historical design decisions were made
- new features can unintentionally conflict with existing workflows
- project documentation becomes outdated quickly
- AI can generate plausible but contextually wrong recommendations
- difficult to trace a feature back to the original user or business need
- small changes can have unexpected downstream impact
- maintaining consistency becomes harder as the product grows

## Goals

- understand the impact of changes before designing
- preserve product and UX continuity
- use AI without losing professional judgment
- reduce repetitive documentation work
- work faster on feature requests
- maintain design-system consistency
- keep project decisions understandable over time

## Needs

- persistent project context
- easy import of existing product knowledge
- strong existing-vs-proposed comparison
- work packages for each change
- change-impact awareness
- design-pattern memory
- evidence and assumption tracking
- non-linear workflows
- useful AI assistance without artificial process enforcement

# Persona 2 — The Multi-Project Product Designer

## Profile

**Role:** Product Designer / UX Designer  
**Experience:** 4–10 years  
**Environment:** Consultancy, agency, internal design team, or multiple product streams  
**Project type:** Multiple existing products

## Characteristics

- frequently switches between projects
- each project has different users, terminology, patterns, and constraints
- may join projects after they are already mature
- often receives partial handovers
- uses notes, folders, Figma files, and AI conversations to keep context
- values speed because of multiple parallel commitments

## Pain Points

- loses mental context when switching between projects
- spends time rediscovering how a product works
- must repeatedly search for old decisions
- hard to remember which assumptions belong to which project
- AI conversations become disconnected from the latest project state
- similar feature names can mean different things across products
- project onboarding takes too long
- difficult to know what documentation is still current

## Goals

- return to any project and immediately understand the current state
- avoid rebuilding context after every project switch
- maintain clean boundaries between project knowledge
- quickly start work on new requests
- reduce manual project setup

## Needs

- strong project memory
- concise project summaries
- active work package list
- recent decisions
- unresolved questions
- artifact relationships
- project-specific AI context
- fast search and retrieval
- clear status of existing vs proposed work

# Persona 3 — The Freelance UX / Product Designer

## Profile

**Role:** Independent UX/Product Designer  
**Experience:** 5–15+ years  
**Environment:** Client projects  
**Project type:** Brownfield products with varying documentation quality

## Characteristics

- frequently inherits products they did not design
- has limited time to understand each client's system
- clients may provide screenshots instead of proper documentation
- must make progress quickly
- needs to explain recommendations clearly
- commonly works alone
- uses AI heavily for speed but must personally verify output

## Pain Points

- onboarding into a client's existing product can consume many unpaid hours
- client information is incomplete or contradictory
- project structure is difficult to reconstruct
- design systems may be informal or inconsistent
- hidden constraints appear late
- difficult to preserve context over long client gaps
- must manually organize research, requirements, flows, and design rationale

## Goals

- understand existing products quickly
- begin meaningful work without full documentation
- maintain professional reasoning
- demonstrate the rationale behind recommendations
- reduce setup effort for each client
- preserve project knowledge between engagements

## Needs

- progressive project ingestion
- screenshot and Figma understanding
- structured project model
- assumption tracking
- work-package organization
- client-facing rationale
- easy re-entry into inactive projects
- minimal mandatory setup

# Persona 4 — The AI-Accelerated Designer

## Profile

**Role:** UX / Product Designer  
**Experience:** 3–12 years  
**Environment:** Any digital product environment  
**Project type:** Existing products  
**AI usage:** High

## Characteristics

- regularly uses ChatGPT, Claude, Stitch, Figma AI, or coding agents
- generates journeys, UI directions, specifications, and code prompts
- comfortable delegating production tasks to AI
- wants to spend more time on decisions and less time producing artifacts
- experiments with new AI workflows frequently

## Pain Points

- every AI tool has only part of the project context
- outputs drift between conversations
- AI may invent unsupported user needs
- generated UI may ignore existing product patterns
- difficult to know what information an AI response was based on
- prompts become long and repetitive
- must manually carry context between Figma, ChatGPT, Claude, and code tools
- rapid production creates more artifacts to manage

## Goals

- make AI aware of the actual product
- reduce repeated prompting
- generate outputs consistent with existing UX decisions
- preserve evidence and assumptions
- move quickly from requirement to design to implementation
- keep human judgment in control

## Needs

- persistent AI project memory
- intelligent context selection
- specialist UX reasoning
- artifact traceability
- design-system awareness
- prompts prepared for downstream tools
- confidence indicators
- ability to challenge AI recommendations

# Persona 5 — The UX Lead Protecting Product Quality

## Profile

**Role:** UX Lead / Principal Designer / Design Lead  
**Experience:** 12–20+ years  
**Environment:** Mature product organization  
**Project type:** Multiple workstreams within established products

## Characteristics

- reviews design work produced by others
- responsible for UX consistency and quality
- frequently sees unnecessary features, weak rationale, and inconsistent patterns
- needs to understand why decisions were made
- does not personally execute every screen
- increasingly reviews AI-assisted work

## Pain Points

- difficult to review the reasoning behind completed designs
- designers may jump directly to UI without enough problem definition
- generated artifacts can give false confidence
- teams repeat previously solved interaction problems
- weak traceability between requirements and designs
- inconsistencies accumulate across workstreams
- critical UX decisions are buried in meetings and messages

## Goals

- improve quality without creating excessive process
- understand rationale quickly
- identify unsupported assumptions
- preserve established design principles
- reduce repeated mistakes
- allow teams to work flexibly while maintaining coherence

## Needs

- decision history
- evidence and confidence tracking
- existing-pattern visibility
- design review support
- change impact
- project-wide consistency checks
- flexible rather than mandatory process controls
