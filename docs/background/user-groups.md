# UX Designer OS — User Groups

## Scope

UX Designer OS is initially designed for individual UX and product practitioners working on existing digital products.

The primary focus is experienced practitioners doing brownfield work rather than beginners learning the UX process.

---

## User Group 1 — Product / UX Designers

### Description

Professional designers responsible for improving and extending existing digital products.

They may hold titles such as:

- UX Designer
- Product Designer
- Senior Product Designer
- UX/UI Designer
- Interaction Designer

### Typical Work

- add new features
- improve existing screens
- redesign workflows
- respond to stakeholder requests
- review usability issues
- update journeys
- work with existing design systems
- prepare developer handoff
- generate or review AI-assisted design output

### Why This Group Matters

This is the primary target group.

Their daily work depends heavily on maintaining context across a product that already exists.

---

## User Group 2 — Senior / Lead Designers

### Description

Experienced practitioners who work across multiple areas of a product and frequently make design decisions that affect wider systems.

Typical titles:

- Senior UX Designer
- Lead Product Designer
- Principal Designer
- UX Lead
- Design Lead

### Typical Work

- evaluate feature requests
- maintain experience consistency
- review other designers' work
- negotiate scope
- identify product-wide impact
- challenge weak requirements
- preserve design-system integrity
- connect business, UX, and implementation concerns

### Why This Group Matters

They are likely to benefit strongly from project memory, traceability, decision history, change impact, and AI-assisted judgment.

---

## User Group 3 — Embedded Designers in Product Teams

### Description

Designers working inside long-running product teams rather than project-based agencies.

They continuously work on the same product or product family.

### Typical Work

- receive backlog items
- work with PMs and developers
- respond to customer issues
- add incremental features
- maintain existing patterns
- participate in refinements
- update designs based on technical constraints

### Why This Group Matters

Their main challenge is not understanding UX methodology.

It is maintaining continuity across months or years of product changes.

---

## User Group 4 — Freelance Product / UX Designers

### Description

Independent practitioners managing several client products at the same time.

### Typical Work

- onboard into unfamiliar existing products
- receive incomplete client documentation
- understand existing UI quickly
- switch between several projects
- maintain project-specific context
- produce deliverables quickly
- communicate rationale to clients

### Why This Group Matters

They experience severe context switching and repeatedly need to reconstruct project understanding.

---

## User Group 5 — Designers Working in AI-Assisted Workflows

### Description

UX and product designers already using tools such as ChatGPT, Claude, Figma AI, Stitch, Cursor, or Claude Code.

### Typical Work

- generate UX artifacts with AI
- create UI prompts
- generate prototypes
- create code-assisted interfaces
- summarize documentation
- analyze requirements
- review AI-generated screens
- use multiple AI conversations for the same project

### Why This Group Matters

They directly experience the fragmentation that UX Designer OS intends to solve.

Their problem is increasingly not generation speed, but context, consistency, traceability, and judgment.

# Secondary User Groups

The following groups may become relevant later but are not primary MVP users.

## Product Managers

Potential needs:

- product context
- decision history
- feature relationships
- change impact
- backlog understanding

## Business Analysts

Potential needs:

- requirements
- feature relationships
- flows
- traceability
- system understanding

## UX Researchers

Potential needs:

- evidence management
- research traceability
- findings linked to product decisions

## Developers

Potential needs:

- design rationale
- implementation context
- interaction specifications
- affected areas
- constraints

## Design Managers

Potential needs:

- review history
- consistency
- project health
- decision quality

These groups should not drive the initial MVP.

---

# Initial Target User

The initial product should be optimized for:

> A mid-to-senior UX or product designer working on one or more existing digital products and already using AI tools as part of their workflow.

Typical characteristics:

- 3–15+ years of experience
- understands UX fundamentals
- does not need a tool to teach a rigid UX process
- works mainly on brownfield products
- frequently receives feature requests and change requests
- works with Figma and product documentation
- increasingly uses AI for analysis, ideation, prototyping, or implementation
- values speed but does not want to lose UX reasoning
